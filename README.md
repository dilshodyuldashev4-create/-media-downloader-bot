# Telegram-бот: скачивание видео + поиск музыки + распознавание (Railway.com)

## Что умеет

- Принимает ссылку на видео с любой платформы, которую поддерживает `yt-dlp`
  (YouTube, TikTok, Instagram, VK, Twitter/X и десятки других), предлагает
  качество кнопками и скачивает.
- Принимает название песни/исполнителя, ищет варианты на YouTube и присылает
  выбранный трек в формате MP3.
- После получения видео можно нажать «Распознать музыку» — бот попробует
  определить трек через Shazam-совместимый сервис (`shazamio`).

## Деплой на Railway.com

1. Залей эту папку в GitHub-репозиторий (или подключи прямо из локальной
   папки через Railway CLI).
2. На [railway.com](https://railway.com) → **New Project** → **Deploy from
   GitHub repo** → выбери репозиторий.
3. Railway сам увидит `nixpacks.toml` и поставит **ffmpeg** и Python 3.11 —
   без этого скачивание видео/аудио будет падать с ошибкой.
4. Открой вкладку **Variables** и добавь:
   ```
   BOT_TOKEN = 123456:ABC-твой-токен-от-BotFather
   ```
   Без этой переменной бот теперь явно завершится с ошибкой в логах
   (`BOT_TOKEN не задана`), а не будет молча висеть.
5. Убедись, что в **Settings → Deploy** тип процесса — **Worker**, а не Web
   (у бота нет HTTP-сервера, слушать порт не нужно). В `Procfile` уже
   прописано `worker: python bot.py`.
6. Нажми **Deploy**. Смотри вкладку **Logs** — там появится
   `Запуск бота...` и дальше все сообщения от пользователей будут логироваться.

## Частая причина "бот не отвечает" на Railway

- **Два активных деплоя одновременно.** Если ты редеплоил проект, а старый
  контейнер не успел остановиться — оба процесса дерутся за
  `getUpdates`, и Telegram отдаёт ошибку `Conflict: terminated by other
  getUpdates request`. В коде уже добавлен `bot.delete_webhook(drop_pending_updates=True)`
  перед стартом polling — это снижает риск, но если ошибка всё равно
  появляется в логах, зайди в Railway → **Deployments** и вручную останови
  старые (не активные) деплои.
- **BOT_TOKEN не задан или неверный** — теперь бот при старте сразу пишет об
  этом в логи и завершает процесс, вместо того чтобы тихо ничего не делать.
- **Нет ffmpeg** — проверь, что `nixpacks.toml` действительно попал в
  репозиторий и Railway использует Nixpacks-билдер (это видно в логах сборки).

## Важные замечания

- **Лимит размера файла**: обычный бот (не self-hosted Bot API сервер) может
  отправлять файлы до ~50 МБ. Для больших видео в высоком качестве нужно
  либо разворачивать свой Local Bot API Server, либо снижать качество.
- **Хранилище в памяти**: `video_cache` и `search_cache` — обычные словари
  в оперативной памяти. На Railway при каждом редеплое/рестарте контейнер
  создаётся заново и кэш обнуляется — это нормально, просто старые кнопки
  "Скачать"/"Выбери трек" после рестарта перестанут работать, пользователю
  нужно будет прислать ссылку/запрос заново. Для персистентности между
  рестартами используй Redis (Railway даёт плагин Redis одной кнопкой) или БД.
- **Правовая сторона**: скачивание видео и музыки с платформ может нарушать
  условия использования этих сервисов и авторские права правообладателей.
  Используй бота только для контента, на скачивание которого у тебя есть
  права.
- Для стабильной работы с YouTube иногда требуется обновлять `yt-dlp`
  (актуальная версия в `requirements.txt`), так как платформы периодически
  меняют защиту.

# Telegram-бот: скачивание видео + поиск музыки + распознавание + админ-панель (Railway.com)

## Что умеет

- Принимает ссылку на видео с любой платформы, которую поддерживает `yt-dlp`
  (YouTube, TikTok, Instagram, VK, Twitter/X и десятки других), предлагает
  качество кнопками и скачивает.
- Принимает название песни/исполнителя, ищет варианты на YouTube и присылает
  выбранный трек в формате MP3.
- После получения видео можно нажать «Распознать музыку» — бот попробует
  определить трек через Shazam-совместимый сервис (`shazamio`).
- **Автоматически сохраняет каждого, кто написал боту, в базу подписчиков.**
- **Админ-панель** (`/admin`): рассылка сообщения (текст/фото/видео/что угодно)
  всем подписчикам одним нажатием + статистика по количеству подписчиков.

## Админ-панель

1. Узнай свой Telegram user id — напиши в Telegram боту **@userinfobot**, он
   пришлёт твой ID (число).
2. На Railway → **Variables** → добавь:
   ```
   ADMIN_IDS = 123456789
   ```
   Если админов несколько — через запятую: `123456789,987654321`.
3. В своём чате с ботом напиши `/admin` — появится панель с кнопками
   **📢 Сделать рассылку** и **📊 Статистика**.
4. Нажми «Сделать рассылку», пришли любое сообщение (текст, фото с подписью,
   видео и т.д.) — бот разошлёт точную копию этого сообщения всем, кто есть
   в базе подписчиков, и покажет, скольким доставлено.
5. Отменить рассылку до отправки — команда `/cancel`.

Для обычных пользователей (не из `ADMIN_IDS`) команда `/admin` ничего не
делает — бот на неё просто не отвечает.

## Персистентность базы подписчиков на Railway

База хранится в SQLite-файле (`subscribers.db` по умолчанию). **Важно**:
файловая система контейнера на Railway эфемерная — при каждом новом деплое
или рестарте сервиса файл создаётся с нуля, и подписчики "теряются" (не
физически, а по факту сбрасывается сама база).

Чтобы база переживала рестарты и редеплои:

1. В Railway открой сервис → **Settings → Volumes → New Volume**.
2. Примонтируй его, например, на путь `/data`.
3. В **Variables** добавь:
   ```
   DB_PATH = /data/subscribers.db
   ```
4. Redeploy сервис.

Без этого шага бот всё равно будет работать и накапливать подписчиков между
сообщениями в рамках одного запуска — просто при редеплое список обнулится.

## Деплой на Railway.com (через Dockerfile)

Проект теперь собирается через **Dockerfile** — это надёжнее автоопределения
билдера (Nixpacks/Railpack иногда сами решают, как ставить Python и ffmpeg,
и могут упасть). Dockerfile ставит ровно то, что нужно: Python 3.11 + ffmpeg.

1. Залей всю эту папку в GitHub-репозиторий (включая `Dockerfile` и
   `.dockerignore`).
2. На [railway.com](https://railway.com) → **New Project** → **Deploy from
   GitHub repo** → выбери репозиторий.
3. Railway должен сам обнаружить `Dockerfile` и использовать его. Если
   нет — зайди в **Settings → Build** и вручную выбери билдер **Dockerfile**
   (путь `Dockerfile`, он уже прописан и в `railway.json`).
4. Открой вкладку **Variables** и добавь:
   ```
   BOT_TOKEN = 123456:ABC-твой-токен-от-BotFather
   ADMIN_IDS = твой-telegram-id
   ```
5. Нажми **Deploy** (или дождись автоматического). Смотри вкладку **Logs**.

Так как в Dockerfile команда запуска уже прописана (`CMD ["python", "bot.py"]`),
`Procfile` больше не нужен — можешь его не создавать.

## Частая причина "бот не отвечает" на Railway

- **Два активных деплоя одновременно** → `Conflict: terminated by other
  getUpdates request`. Останови старые (не активные) деплои во вкладке
  Deployments.
- **BOT_TOKEN не задан или неверный** — бот при старте пишет об этом в логи
  и завершает процесс.
- **Сборка падает на установке Python/пакетов** — убедись, что Railway
  реально использует Dockerfile (Settings → Build → Builder = Dockerfile),
  а не Nixpacks/Railpack.
- **В репозитории лежит не тот файл `bot.py`** — если раньше на Railway
  разворачивался другой проект, убедись, что в GitHub-репозитории именно
  этот код, а не старый.

## Важные замечания

- **Лимит размера файла**: обычный бот может отправлять файлы до ~50 МБ.
- **Рассылка и лимиты Telegram**: между сообщениями рассылки стоит небольшая
  пауза (0.05 сек), чтобы не упереться в анти-флуд лимиты Telegram
  (~30 сообщений/сек). Для очень больших баз (десятки тысяч) рассылка может
  занять время — это нормально.
- **Правовая сторона**: скачивание видео и музыки с платформ может нарушать
  условия использования этих сервисов и авторские права правообладателей.
  Рассылка рекламы через Telegram также должна соответствовать
  [Условиям использования Telegram](https://telegram.org/tos) — избегай
  спама тем, кто явно не давал согласия взаимодействовать с ботом.
- Для стабильной работы с YouTube иногда требуется обновлять `yt-dlp`.
